#+title: BOSH

BOSH is a multi-cloud virtual machine orchestrator by Cloud Foundry.

* Deployment modes

| Name       | Description                                                                                                                                                                                            |
|------------+--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Multi VMs  | The classical BOSH mode as used by many companies. The BOSH server runs alone on its VM, and all managed nodes are on their own VM too.                                                                |
| Single VM  | The classical BOSH-Lite mode, where one signle VM runs both the BOSH server, and managed nodes. The BOSH server is on the VM itself, whereas managed nodes are deployed in containers, on the same VM. |
| Hybrid VMs |                                                                                                                                                                                                        |

Note that generic config support is not a requirement for multi-config support (such as in cloud config), neither does it enforce any consistent multi-config support.

** Deploy config

Unlike the other predefined config types in BOSH, the deploy configs are pulled and parsed by the BOSH CLI (v7.5.0 onwards) directly, rather than by the BOSH Director.

The syntax is as follows:

#+BEGIN_SRC yaml
  include:
    - deploymentName
  exclude:
    - deploymentName
  flags:
    - fix-releases
    - fix
    - recreate
    - recreate-persistent-disks
#+END_SRC

* Reconciliation

Generally, BOSH is quite conservative with reconciliation, and can be controlled through "update.canaries" and "update.max_in_flight". The main exception to this is when removing an availability zone.

Reconcilliation does not occur for these scenarios:

- `bosh stop --hard [instance_group]/[instance_id]`


** Deployment update propagation


Deployments' virtual machines are updated in this order:
1. The bootstrap VM
2. All virtual machines of the first availability zone
3. All virtual machines of the second availability zone
4. etc.


** Scaling in

The instance with greater index (i.e. the latest that hsa been added) is removed first.
